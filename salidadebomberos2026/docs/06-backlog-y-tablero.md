# Backlog y forma de trabajo

## Tablero mínimo

El equipo debe mantener las tareas en estas columnas:

`Backlog → Pendiente → En curso → Revisión → Terminado`

Cada tarjeta debe tener historia o tarea, responsable, prioridad, criterio de finalización y evidencia.

## Responsabilidades

Los nombres deben completarse con los integrantes reales del equipo. Los roles son colaborativos y no exclusivos.

| Área | Responsable principal | Participación compartida |
|---|---|---|
| Coordinación y cliente | Completar | Todo el equipo. |
| Interfaz y accesibilidad | Completar | Todo el equipo prueba la UI. |
| Datos y persistencia | Completar | Todo el equipo explica el modelo. |
| Backend y seguridad | Completar | Todo el equipo revisa permisos. |
| Pruebas y documentación | Completar | Todo el equipo aporta evidencias. |

## Revisión semanal

Para cada semana registrar fecha, asistentes, avances, bloqueos, feedback del cliente, decisiones y tareas de la semana siguiente. El documento debe mantenerse actualizado con el historial real del equipo.

## Evidencias recomendadas

Capturas del tablero, enlaces a issues, actas breves, pull requests, commits y capturas de la aplicación. Las evidencias deben identificar fecha y autor sin reemplazar la explicación individual durante la defensa.
